# Ignition Integration POC — Maximo & Axxos OEE

A working proof-of-concept demonstrating **Ignition as a central connect + transform layer**, handing off processed equipment/alarm data to two independent Python integration pipelines that deliver it to **Axxos OEE** (production monitoring / OEE) and **Maximo** (maintenance management).

Full write-up, use case description, and architecture diagram: see [`docs/POC_Documentation.md`](docs/POC_Documentation.md)

## Prerequisites

- Docker Desktop
- Ignition (local instance, Designer + Gateway)
- Python 3 with `paho-mqtt`, `requests`, and `flask` installed

## Quick start

1. **Start the MQTT broker:**
   ```bash
   docker run -d --name mosquitto -p 1883:1883 -p 9001:9001 \
     -v ${PWD}/scripts/mosquitto.conf:/mosquitto/config/mosquitto.conf \
     eclipse-mosquitto
   ```

2. **Run the fake data simulator:**
   ```bash
   pip install paho-mqtt
   python scripts/simulate_plc.py
   ```

3. **In Ignition:**
   - Create a project, e.g. `POC_Maintenance_Integration`
   - Install the free **MQTT Distributor** and **MQTT Engine** modules
   - In MQTT Engine, add a server connection to `tcp://localhost:1883`
   - Add a **Custom Namespace** with MQTT topic `plant/#`
   - Create a `default` provider memory tag named `ProcessedBatch` (String)
   - Create a **Tag Change Script** on tag `[MQTT Engine]plant/line1/events`, and paste in the contents of [`ignition/ignition_tag_change_script.py`](ignition/ignition_tag_change_script.py)
   - Make sure the folder `C:\poc\` exists (or change the file path in the script) — this is where Ignition writes `processed_events.jsonl`

4. **Run the two integration pipelines** (each in its own terminal):
   ```bash
   pip install requests
   python scripts/pipeline_axxos.py
   python scripts/pipeline_maximo.py
   ```

5. **Run the mock dashboards:**
   ```bash
   pip install flask
   python scripts/dashboard.py
   ```
   - Axxos OEE dashboard: http://localhost:8084
   - Maximo dashboard: http://localhost:8083

Once everything is running, alarm events generated by the simulator flow all the way through Ignition and into both live dashboards automatically.

## Notes

- Ignition 8.3.x expects the Tag Change Script entry-point function to be named `onTagChange(...)`, not the older `valueChanged(...)`.
- The shared file (`processed_events.jsonl`) is a deliberately simple handoff point for this POC — a production version would more likely use MQTT publish or a REST endpoint from Ignition instead.
- Ports 8083/8084 are used for the mock dashboards so they don't conflict with anything else already running on 8081/8082.
